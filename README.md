## Contenido del documento

### 1. Matriz Comparativa del Framework

| Elemento | Definición | Objetivo | Fidelidad | Momento del Ciclo |
|---|---|---|---|---|
| **Wireframe** (ESQUELETO) | Representación esquemática de baja fidelidad en escala de grises | Validar estructura, arquitectura de información y flujo funcional | BAJA (Low-Fi) | Inicio: Descubrimiento y Definición |
| **Mockup** (PIEL) | Representación visual estática de alta fidelidad, pixel-perfect | Validar identidad visual, legibilidad, consistencia de marca | ALTA Estática (High-Fi) | Mitad: Diseño Visual UI |
| **Prototipo** (CUERPO EN MOVIMIENTO) | Simulación interactiva y navegable | Validar interacción, usabilidad, flujo completo y viabilidad | VARIABLE: Low a High-Fi Interactiva | Transversal, crítico pre-desarrollo |

### 2. Ventajas y Limitaciones Críticas
- **Wireframe:** Rapidez y bajo costo, pero no transmite experiencia real ni es testeable con usuarios.
- **Mockup:** Valida estética y Design System, pero es estático y oculta errores de flujo.
- **Prototipo:** Único método para test de usabilidad real (ahorra hasta 70% de retrabajo), pero requiere más tiempo y herramientas.

### 3. Ejemplo Práctico Unificado
Aplicado a una app móvil FinTech "Capital" - Dashboard de Gastos Mensuales, mostrando la misma pantalla en tres evoluciones (Wireframe → Mockup → Prototipo High-Fi en Figma).

### 4. Conclusión Estratégica - Regla de Decisión
- Si validas **QUÉ se construye** → Wireframe
- Si validas **CÓMO SE VE** → Mockup
- Si validas **CÓMO SE SIENTE Y FLUYE** → Prototipo

**Error crítico:** Saltar del wireframe directo a desarrollo sin mockup ni prototipo genera un producto funcionalmente correcto pero visualmente pobre e inusable. El costo de corrección en código es 10x superior al de diseño (Principio de Boehm).

**Estándar académico recomendado:** Wireframe → Test de estructura → Mockup + Design System → Prototipo High-Fi → Test de usabilidad (n=5) → Handoff a desarrollo.
